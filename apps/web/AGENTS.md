# Web application rules

- The web app is a platform adapter and presentation layer. Keep simulation and compatibility rules in platform-independent packages.
- During the Remix parity phase, visual parity with inspected Remix HTML, CSS, assets, runtime, and screenshots takes priority over redesign. Do not invent generic dashboard styling or modernize legacy UI without an approved, documented exception.
- The desktop Remix view is the initial visual oracle. Mobile must retain systems, content, hierarchy, state, and identity; redesign is post-parity unless recorded as an exception.
- Do not add gameplay during foundation scaffolding. Record visual test state, viewport, and source evidence in project documentation.
