# Execution plans

Use an execution plan for multi-step work that spans files, research, or several validation stages. Small focused edits do not need a plan.

## Location and upkeep

- Keep phase plans in docs/plans and active work notes with the relevant plan.
- Identify the objective, scope, reference/evidence, dependencies, ordered work, validation commands, documentation updates, and remaining risks.
- Record progress and findings as work proceeds. A plan is a working document, not a decorative proposal.
- Do not write unsupported mechanics as planned facts; list them as research questions until verified.

## Completion

Before closing a plan, run its validation, update the relevant parity matrix and project status, record accepted exceptions, and ensure the resulting commits are validated Conventional Commits.

For parity work, use the workflow in docs/knowledge/parity-contract.md. The canonical plan index is docs/plans/README.md.
