## Platform baselines

Chromium rasterizes text differently on Windows and Linux, so Linux E2E selects `-linux` screenshots where they have been captured. The pinned Linux baselines use Playwright Chromium `153.0.8010.12` on Ubuntu 24.04 in WSL; the Mining screen hash also matched the `ubuntu-latest` CI runner. The current visual corpus has Linux pairs for the all-unlocked Story pages, fresh Mining and Settings, and the craft-selector crop. Fresh Game Start, first-Mud, first-Paper, first-Blacksmith, first-Clay, first-Stone, 10,000-Money, natural millionaire (initial and scrolled), controlled Spooky Bone Story, and natural millionaire-to-Spooky-Bone Story have Windows source baselines only: their Linux E2E cases still verify the live state and rendered milestone order, while deferring screenshot comparison. `tests/parity/visual-baselines.test.ts` pins the exact twenty-two missing Linux counterparts so the gap stays visible. Only rendered layout measurements may differ between an available Windows/Linux pair.

To add or update a Linux baseline, capture it on Linux (for example in WSL). `pnpm reference:mining-screen:capture` writes the `-linux` Mining and craft-selector fixtures directly. `pnpm reference:story-runtime:capture` writes fresh Story, first-Mud, first-Paper, first-Blacksmith, first-Clay, first-Stone, 10,000-Money, both natural millionaire views, controlled and natural Spooky Bone, all-unlocked Story pages, and Settings screenshots to `.research/outputs/story-runtime/`; copy the selected PNG to `tests/fixtures/visual/<name>-linux.png` and derive its sidecar from the Windows sidecar with the new `screenshotSha256`, `screenshotPath`, and capture measurements. Review the pair, remove that fixture from the Linux-gap list in `tests/parity/visual-baselines.test.ts`, then run `CI=true pnpm test:e2e` on Linux before committing. The current managed PowerShell session cannot start WSL (`Wsl/Service/E_ACCESSDENIED`), so those Linux captures remain outstanding here.

## Capture workflow

Record the canonical Remix save/state, theme, browser, and viewport for each baseline. Initial desktop target viewports are 1366x768, 1440x900, 1920x1080, and 2560x1440, with light and dark themes. Mobile preserves behavior and hierarchy; there is no authoritative modern Remix mobile visual oracle.

The read-only Remix Story probe produces disposable source screenshots for all-unlocked chapters 1 and 9 and fresh Settings light/dark states in `.research/outputs/story-runtime/`. Recreate them with `pnpm reference:story-runtime:capture`; the first-chapter capture is also the source for the approved Story baseline above. Recreate both fresh Mining themes with `pnpm reference:mining-screen`; explicitly reviewed source-baseline updates use `pnpm reference:mining-screen:capture`. Review each state and fixture metadata before adding or changing a baseline.

## Browser and Canvas requirements

Story runtime, fresh Mining screen, and Canvas captures must use the Chromium version bundled with the pinned Playwright package. Install it with `pnpm exec playwright install chromium`; capture mode rejects system Chrome and an explicit alternate browser. The source capture records Chromium `153.0.8010.12`, and read-only verification rejects a different version. The launcher disables font hinting to reduce platform-dependent text and Canvas differences. Source-only RGBA baselines for the Story's 48 preview occurrences are under `tests/fixtures/visual/remix-story-mine-objects/`; `tests/e2e/mine-object-renderer.spec.ts` also renders all 920 captured object levels in both the live pinned Remix runtime and Beyond, comparing PNG hashes in the same Chromium session. These object Canvas checks do not certify the surrounding UI.
