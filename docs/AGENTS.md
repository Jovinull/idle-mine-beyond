# Documentation rules

- `docs/knowledge/` is the canonical memory of this project. Update the responsible focused document in the same work unit as material changes to source understanding, behavior, architecture, parity, status, or decisions.
- Label claims as verified legacy behavior, project decision, hypothesis, known legacy defect, or post-parity proposal. Preserve source links and exact pins where relevant.
- Keep bootstrap assimilation as a cross-reference, not a competing copy of the original input. Do not state unverified assumptions as facts.
- Keep `PARITY_MATRIX.md`, `BEHAVIORAL_EXCEPTIONS.md`, and `POST_PARITY_BACKLOG.md` authoritative for their respective records.
