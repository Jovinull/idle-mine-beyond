# Phase plans

Plans capture outcomes and validation gates without pretending that unresearched game rules are known. A phase plan may remain “not started” while its required evidence is collected.

| Plan                                                                   | Outcome                                          |
| ---------------------------------------------------------------------- | ------------------------------------------------ |
| [Phase 0 — Reference freeze](phase-00-reference-freeze.md)             | Freeze sources and establish behavior extraction |
| [Phase 1 — Deterministic core](phase-01-deterministic-core.md)         | Platform-independent simulation foundation       |
| [Phase 2 — Content extraction](phase-02-content-extraction.md)         | Versioned source-derived definitions             |
| [Phase 3 — Crafting compatibility](phase-03-crafting-compatibility.md) | Exact stochastic pickaxe crafting                |
| [Phase 4 — Resources and upgrades](phase-04-resources-upgrades.md)     | Money, Gems, PC, Wisdom, Powers, upgrades        |
| [Phase 5 — Procedural generation](phase-05-procedural-generation.md)   | Deterministic reference-matching object IDs      |
| [Phase 6 — Saves and offline](phase-06-saves-offline.md)               | Legacy import and controlled time                |
| [Phase 7 — Desktop UI parity](phase-07-desktop-ui.md)                  | Source-faithful presentation and interactions    |
| [Phase 8 — Visual certification](phase-08-visual-certification.md)     | Screenshot parity evidence                       |
| [Phase 9 — Native packaging](phase-09-native-packaging.md)             | Tauri platform integration                       |
| [Phase 10 — Parity certification](phase-10-parity-certification.md)    | Reviewed parity-v1 release gate                  |

Update plans with evidence, completed work, and new blockers. Keep one active execution plan for major work; do not create implementation details unsupported by the reference.
