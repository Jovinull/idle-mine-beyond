# Story system

Story behavior is a compatibility target. Preserve the source order, chapter assignment, text, jokes, grouping, embedded mine-object previews, and interactions. Source oddities are not permission to edit the story.

## Verified legacy behavior

- Remix has nine ordered chapter titles and 61 ordered milestones (indices 0–60). Each milestone has a condition expression, an objective that is either literal text or a function, and a page index. The probe preserves every condition, objective kind, dynamic function source/output at initial state, key, index, and page.
- The 61 distinct condition expressions are exercised at their relevant boundaries in the oracle. - `storyUnlocked(key)` evaluates the condition directly. `storyDisplayed(key)` is true when that condition is true and the selected page equals the milestone page; it does not consult `highestUnlocked`.
- `getNextStoryText()` scans from the first milestone and returns the objective for the first currently false condition. The source has 38 function-valued objectives. Beyond stores their typed literal, mine-level, or formatted-number forms and renders them through injected number-formatting functions. The corpus captures all 38 outputs at highest mine-object levels 0, 12, 214, and 215, and captures the two formatter-sensitive objectives with all 40 notations (152 level samples and 80 notation samples).
- `getMaxStoryPage()` scans milestones from the end and returns the page of the last currently satisfied condition. Its source fallback is page 3, but the initial `gameStart: true` condition makes the captured fresh-game maximum page 0.
- Page increase is `Math.min(page + 1, maxPage)`; page decrease is `Math.max(page - 1, 0)`. Increasing from a saved page beyond the current maximum snaps to that maximum.
- The `index.html` Story article keeps the same `.story-milestones` element around page changes. Beyond preserves this navigation behavior across its source-template update.
- On each main-loop frame, `Scripts/main.js` calls `refreshStoryNotifications()` after its save check. The refresh scans every remaining index from `highestUnlocked + 1` through the end; it does not stop at an unsatisfied condition. Every true condition advances `highestUnlocked` to that index and increments `notifications` once.

## Beyond implementation

`packages/core/src/remix-story.ts` implements the typed condition evaluator, source-ordered notification transition, maximum-page lookup, direct-condition visibility selector, next locked milestone selector, objective text renderer, and page navigation clamps. `remix-story-interactions.ts` returns the exact alert/error-log effects for the debt joke without mutating Money and builds its button label with injected formatting. `remix-story-tabs.ts` models the tab state transition and emits delayed scroll-restore or number-format-select effects. Objective and button formatting are injected so the core remains independent of the formatter package and UI. These are pure core slices: they receive state and definitions and have no UI, save, timer, or browser dependency.

Vitest compares every condition boundary, six controlled state transitions, the two-stage high-water sequence, dynamic objective strings, all 40 formatter outputs, four debt-interaction balances, and four tab/scroll scenarios with the pinned corpus. Playwright Chromium performs the same comparisons in a browser harness. `scripts/sync-story-template.mjs` generates `packages/content/src/remix-story-template.json` from the reviewed markup and runtime fixtures; `pnpm content:check` verifies it against the pinned source metadata.

`apps/web/src/lib/remix-story-template.ts` translates the captured Vue article into browser HTML without changing source block order, including duplicate `mineUniverse` blocks and Colossia's nested conditional children. It substitutes the captured page, chapter, objective, number-format and long-goal values, escapes interpolated strings, translates page/objective visibility and action bindings, and turns fixed `<mine-object>` elements into Canvas elements. It fails closed if an unsupported source directive or interpolation appears. `StoryPanel.svelte` supplies the core milestone conditions and objective, preserves page navigation, renders all nine captured chapters, and exposes the debt joke's alert/log effects through a callback or a local browser event. The app route mounts this component in its Story tab, derives it from live simulation state, and wires page, notification, tab, scroll, and debt-log effects through the browser boundary. Playwright covers fresh in-app Story, natural progress through Spooky Bone, controlled all-unlocked/progression imports, the `PAY` alert and visible mining log, Story page/scroll save and reload, notification clearing, and an idle mining break that produces the next Story notification. Full-screen app-route screenshot tests compare fresh Game Start, first-Mud, first-Paper, first-Blacksmith, first-Clay, first-Stone, 10,000-Money, natural millionaire initial/scrolled views, natural millionaire-to-Spooky-Bone, controlled Spooky Bone, and all nine all-unlocked page indices in light and dark at 1440x900 on Windows; other states, screens, and viewports remain open.

Vitest covers the source-derived template conversion, captured chapter labels and order, nested Colossia blocks, duplicate final blocks, unresolved Vue syntax, and HTML escaping. Playwright mounts the standalone component with the captured fresh state and the all-unlocked oracle state, compares all nine page headings, top-level milestone order/text/image paths/Canvas levels, exercises both navigation directions and the source-observed 100px chapter-scroll preservation, checks selected captured computed styles, verifies the above-threshold `PAY` alert/log event, and waits for the 48 preview canvases to render. This proves the exercised route and save path, not full app visual parity, every progression-triggered notification, all historical save variants, theme/viewport coverage, or complete gameplay.
